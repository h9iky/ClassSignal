# ClassSignal

Начальная версия образовательной платформы BIL Turkistan. Сейчас есть веб-интерфейс для учебного плана и тем, а также API на FastAPI; это фундамент проекта, а не готовая школьная система.

> **Важно о безопасности:** авторизация пока не реализована. Все endpoints, включая создание и изменение данных, доступны без входа в систему. Не размещайте этот прототип в публичном интернете и не используйте его для реальных данных учеников.

## Требования

- Python 3.11 или новее
- SQLite (входит в стандартную поставку Python)

## Установка и запуск

Команды ниже приведены для Linux/macOS. В Windows вместо `source .venv/bin/activate` используйте `.venv\\Scripts\\Activate.ps1`.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` можно изменить `DATABASE_URL`. По умолчанию используется файл SQLite `classsignal.db` в текущей папке:

```dotenv
DATABASE_URL=sqlite:///./classsignal.db
```

Создайте таблицы через миграцию и запустите сервер:

```bash
alembic upgrade head
uvicorn app.main:app --reload
```

Сайт будет доступен по адресу <http://127.0.0.1:8000/>. Интерактивная документация API — <http://127.0.0.1:8000/docs>.

## Веб-интерфейс

Главная страница позволяет просматривать темы, искать и фильтровать их по предмету, четверти и статусу; создавать предметы и четверти; создавать и редактировать темы. Интерфейс написан на обычных HTML, CSS и JavaScript и использует тот же API, без дополнительных frontend-зависимостей.

Важно: статус темы пока только метка, он не скрывает черновики и архив от посетителей. Все данные и операции API остаются открытыми до реализации авторизации.

## Endpoints

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/health` | Проверить, что API отвечает |
| `GET` | `/api/v1/subjects` | Получить предметы |
| `POST` | `/api/v1/subjects` | Создать предмет |
| `GET` | `/api/v1/quarters` | Получить четверти |
| `POST` | `/api/v1/quarters` | Создать четверть |
| `GET` | `/api/v1/topics` | Получить темы; доступны фильтры `subject_id` и `quarter_id` |
| `POST` | `/api/v1/topics` | Создать тему |
| `GET` | `/api/v1/topics/{topic_id}` | Получить одну тему |
| `PATCH` | `/api/v1/topics/{topic_id}` | Частично изменить тему |

Коды `422`, `404` и `409` означают соответственно некорректные входные данные, отсутствие записи или конфликт уникальности.

Создание четверти добавлено в Stage 1, чтобы API позволял создать все необходимые записи для первой темы. Год учебы хранится строкой, например `2025-2026`; номер четверти — от 1 до 4.

## Миграции

Модели описывают структуру таблиц, а Alembic-миграция применяет изменения к базе. Для новой базы выполните `alembic upgrade head`. После изменения моделей создавайте новую миграцию командой:

```bash
alembic revision --autogenerate -m "описание изменения"
```

Перед применением автосгенерированную миграцию нужно прочитать и проверить. Чтобы отменить последнюю миграцию, выполните `alembic downgrade -1`.

## Тесты

```bash
pytest
```

Тесты используют отдельную временную SQLite-базу и не изменяют вашу локальную `classsignal.db`.

## Структура проекта

- `app/main.py` — создание FastAPI-приложения.
- `app/routers.py` — HTTP endpoints и ответы с кодами ошибок.
- `app/schemas.py` — проверка входных данных и формат ответов (Pydantic).
- `app/models.py` — таблицы SQLAlchemy и ограничения базы данных.
- `app/database.py` — подключение и создание сессии базы данных.
- `app/static/` — HTML, CSS и JavaScript веб-интерфейса.
- `migrations/` — история схемы базы данных для Alembic.
- `tests/` — автоматические проверки API.

Для будущего перехода на PostgreSQL установите драйвер `python -m pip install "psycopg[binary]"` и укажите `DATABASE_URL` вида `postgresql+psycopg://USER:PASSWORD@HOST:5432/DB_NAME`. Не храните реальные пароли в Git. Модели и запросы используют SQLAlchemy и не зависят от SQLite-специфичного SQL.

## Ограничения текущего этапа

- Нет регистрации, входа, ролей и проверки прав учителей.
- Пока не реализованы пользователи, классы, материалы, задания и обратная связь.
- `teacher_id` в теме отложен до появления таблицы пользователей и проверки назначений учителей.
- Статус темы (`draft`, `published`, `archived`) хранится, но публикация пока не ограничивает чтение.
- Проверка `/health` подтверждает только, что отвечает процесс API; она не проверяет доступность базы данных.
